# 视频专区的后三块：场景 / 表情动作 / 数字人

日期：2026-09-27 · 承接 `video-zone-design-2026-09-27.md`（那一份定了专区「音乐 / 场景 / 表情动作」
三块的结构）。音乐那一块已经上线；这一份说的是**后三块以及它们共用的那个隐私资料库**。

用户要的四件事，按他自己的说法是**同一种设计思路**：

> 上传自己的素材 → **隐私资料库** → 按提示词/文本生成 → 观察效果、修正 → **生成历史** → 选用

三块（场景、表情动作、数字人）都是这个形状，所以下面先给事实，再给一份共用的设计，最后是
**要你定的两件事**。

---

## 一、事实基线（都是查过盘 / 跑过的，不是推测）

### 已经能跑的

| 链路 | 需要的模型 | 在盘上 | 节点 | 结论 |
|---|---|---|---|---|
| 音乐（ACE-Step 1.5） | `ace_step_1.5_turbo_aio` 4.4G + qwen 双 CLIP + vae | ✅ | ✅ 内置 | **已上线** |
| 照片驱动的动作动画 | `wan2.2_ti2v_5B_fp16` 9.3G、`umt5_xxl_fp16` 11G、`wan2.2_vae` 1.3G | ✅ | ✅ 内置 | **能跑** |
| 图生视频 14B | `Wan2_1-I2V-14B-480p_fp8_scaled_KJ` **16G**（今天 08:04 下完） | ✅ | ✅ 内置 | 能跑 |

### 差一步的

| 链路 | 缺什么 | 证据 |
|---|---|---|
| **口播 / 口型同步（InfiniteTalk）** | **只缺一个节点包** —— `ComfyUI-WanVideoWrapper` | 补丁 `model_patches/wan2.1_infiniteTalk_single_fp16.safetensors` ✅、中文音频编码器 `audio_encoders/wav2vec2-chinese-base_fp16` 181M ✅、底座 14B 16G ✅ —— **模型全齐**；而 `custom_nodes/` 里只有 `ComfyUI-AnimateDiff-Evolved`，**没有 WanVideoWrapper**。`fetch-wan14b.sh` 的注释写得很清楚：那条链一直起不来就是因为底座只下到 1.7G/15.5G。底座今天补齐了，于是**现在是节点包的问题**。 |

⚠️⚠️ **一条必须说清的事**：内置工作流 `wan2.2-reference-person.json` 自己的注释写着

> *Photo-conditioned motion; **silent and NOT speech/lip synchronized**. Add cloned narration separately.*

也就是说，本机现在能做的是**照片驱动的「有动作的无声动画」**，旁白要用克隆音色**另外配**（`synthesize_speech`
已经有，`voices/user-medical/` 里也已经有登记的克隆音色）。`samples/数字人样片/分身样片-1080x1920-带旁白.mp4`
是这种「无声动画 + 叠旁白」的产物，**不等于口型对上了**。要确认嘴部是否跟着动，得看一眼那个样片
（我这边看不了图，云端视觉通道在限流）。

### 阻塞的

| 链路 | 为什么 |
|---|---|
| **场景（干净的背景画面）** | 需要**文生图或图像编辑**能力：① 本机 ComfyUI 的 checkpoints 里**只有音乐模型**，没有 SDXL / Flux 之类；② 云端 MetaChat 有 15 个图像模型、provider 是启用的，但账号**额度已用尽** —— 实测原话 `You exceeded your current API quota. Please purchase the API points.`（走应用自己的网络出口才拿到这句；直连只会看到 Cloudflare 的 403/1010）。 |

⚠️ 场景有一个**绕得过去但慢**的做法：`wan2.2 ti2v` 是**文/图生视频**，接受文本提示词，所以可以
「生成一段空镜视频 → 抽一帧当背景板」。代价是它按视频算时间（实测同类 14B 出 5 秒要 **27 分钟**；
`make_animation` 那套逐帧画 6 秒只要 **1.9 秒**，但那是机制动画、不是实景）。**慢 300–500 倍**，
而且要先抽帧。所以它算「能做」，不算「好用」。

### 速度这条也要摆在明面上

| 做法 | 6 秒成片耗时 | 画幅 |
|---|---|---|
| `make_animation`（逐帧画，机制/示意） | **1.9 秒** | 任意（含 9:16） |
| ComfyUI 扩散视频（wan2.2 系） | **807–1647 秒** | 16:9 为主 |

所以**机制镜头用 `make_animation`，人脸/实景才用扩散** —— 这条判据已经写进群里了。

## 二、共用的设计：四个抽屉 + 一条流水线

三块要的东西其实是同一套，所以**只建一套**（这也是「用户可加的模块」一直以来的规矩：
`workflows/` `layouts/` `voices/` `music/` 四类，**不再发明第五种做法**）。

```
        上传（本机、不上传任何地方）
                 │
        ┌────────▼─────────┐
        │  隐私资料库       │  人物照片 / 场景空镜 / 表情动作素材
        │  （本机私有）     │  每份素材 = 一个目录 + sidecar（谁、什么时候、什么用途、能不能用）
        └────────┬─────────┘
                 │ 按名字引用（和 voices/ 一样：`asset: 我的形象`）
        ┌────────▼─────────┐
        │  生成             │  文本/提示词 → 产物；参数全部记下来
        │  观察 → 修正 → 再生成（同一素材的多个版本并排）
        └────────┬─────────┘
                 │
        ┌────────▼─────────┐
        │  生成历史         │  每次生成留一条：素材、参数、产物、耗时、你看过没有
        │  （可回退、可选用）│
        └────────┬─────────┘
                 │
        ┌────────▼─────────┐
        │  选用             │  挑中的进片子；和素材库一样按名字引用
        └──────────────────┘
```

### 隐私资料库（三块共用的地基）

**为什么要独立说它**：它是三块里唯一**不依赖任何生成模型**的部分 —— 今天就能建，而且建好之后
三块接上就只剩接线。

* 位置：`<数据目录>/studio/`（**不是群工作目录，也不是知识库**）
* 每份素材一个目录 + 一个 sidecar：`{"title","kind","note","created","source":"本机上传"}`
* ⚠️ **不进群、不进知识库、不进任何外发路径**。这与器械参考库**故意相反** —— 那个是「内部参考、
  可以拷进每个群」；这个是「你自己的照片，谁都别想顺手拿到」。所以它需要一条**明确的边界**：
  成员**默认看不见**它，只有用 `asset:` 引用时才把**那一份产物**（不是原始素材）交出去。
* 可检索：按人物 / 场景类型 / 表情标签。标签是**你打的**，不用模型猜。

### 生成与迭代

* 一次生成 = 一条记录：素材、参数、产物路径、耗时、**你有没有看过**（`reviewed`）
* 「观察效果进行修正」= 同一素材的版本列表，并排看，挑一个；**不覆盖旧的**（旧版本还可能在片子里）
* ⚠️ 版本号与产物名分开：产物名告诉你它是什么，版本号告诉你它第几次

### 生成历史

* 与素材库分开：素材是**输入**，历史是**发生过什么**
* 可回退：从历史里把某次参数重新跑一遍
* 可选用：挑中的产物进 `选用/`，片子和成员按名字引用它

## 三、要你定的两件事

### ① 「按文本生成表情动作」——你要的是哪一种？

这三种的技术代价差很多：

| | 你要的效果 | 现在能不能做 |
|---|---|---|
| **A. 动作/情绪描述** | 写「她微笑，慢慢转头看向镜头」，出一段有那种情绪的动画 | ✅ **能做** —— wan2.2 ti2v 接受文本提示词，照片作首帧。**但做不到精确控制**（笑到什么程度、眼睛看不看镜头，只能靠多试） |
| **B. 精确面部表情** | 指定「眉头皱起 + 嘴角上扬 30%」这种参数级控制 | ❌ 本机没有对应的驱动链（LivePortrait 一类）；`custom_nodes` 里只有 AnimateDiff |
| **C. 只是镜头运镜** | 推、拉、摇、移 | ✅ 已有（`assemble` 的 camera），不用新做 |

### ② 先做哪一块？

| 选项 | 现在就能开始？ | 说明 |
|---|---|---|
| **隐私资料库 + 生成历史**（地基） | ✅ **立刻** | 不依赖生成模型。三块都要用它，先建它最省事 |
| **表情动作** | ✅ 可以（按 A） | 用 wan2.2；慢，而且无声 |
| **数字人** | ✅ 可以（无声形象）；**要口型**就还差一个节点包 | 装 `ComfyUI-WanVideoWrapper` 才有口型同步 |
| **场景（干净背景）** | ❌ 阻塞 | 要么给云端买点数，要么往本机下一个图像模型（SDXL 一类） |

---

## 四、我的建议

1. **先建隐私资料库 + 生成历史**（地基，今天可做，不依赖任何模型）
2. 同时**装那个节点包**（`ComfyUI-WanVideoWrapper`）—— 它把 InfiniteTalk 那条链的**最后一公里**补上，
   而模型早就齐了；装它比下模型便宜得多
3. 表情动作按 **A** 接上，先出一版看效果（接受「慢、无声」，旁白另配）
4. 场景那块等你决定充点数还是下模型 —— 在此之前它只能在页面上写着还差什么
