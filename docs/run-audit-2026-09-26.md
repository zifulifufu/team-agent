# 一次真实运行的机制审计与修复（2026-09-26）

三个实测群（`实测·介入术式科` / `实测·前交通动脉` / `实测·冗长扩张动`）各跑过一轮真实任务，
**三组都有失败**。本文记录**从运行结果反推出来的机制问题**与已做的修复。

审计方法：只读打开 `~/.team-agent/team-agent.db`，逐条读 `messages.meta.tools`（每次工具调用的
status / args / preview），再用 `toolcall.strip_hidden` 反查"正文里还剩多少协议残留"。
**没有替任何成员执行任务**，也没有改写任何历史数据。

## 一、最贵的一条：长文档被输出上限截断 → 整组任务零交付

`冗长扩张动` 群的任务是 3000 字综述。审计到的原文：

```
RuntimeError: 模型回复被输出上限截断，未执行不完整的工具参数。请把长文档拆成较小章节。
```

模型把整篇正文塞进**一次** `write_document` 调用 → 超出模型输出上限 → 路由器**把整个调用丢掉**
（这是对的：不完整的 JSON 不能执行）→ **连丢四次**，两个不同成员都栽在这里 → 该群最终**没有任何交付物**。

程序侧缺的是"**分节写**"这条路。修：`write_document` 增加 `mode` 参数。

- `mode=replace`（默认）：覆盖，第二稿仍这么交。
- `mode=append`：把这段正文**接在文件已有内容后面**。第一节用 `replace`，之后每节一次 `append`，
  每次 body 建议 ≤1500 字。
- 返回里明确告诉成员：「**接在**已有内容后面：调用前已有 N 字，上面的长度是**现在全文**的长度；
  还没写完就用 `mode=append` 继续，**绝不把全文塞进一次调用**」。

⚠️ 实现时踩到的坑（已由测试守住）：`_existing_body` 第一版把文件首行标题删掉（想避免标题重复），
而 append 又不再写标题 → **标题被永久删掉**。教训："避免重复"的清理逻辑，如果同时删掉"不再重新生成"
的东西，就是数据丢失。

## 二、工具调用方言：三种形态没被识别

| 形态 | 例子 | 后果 |
|---|---|---|
| 裸 JSON（无标签） | `…再开始生成动画。{"name": "write_document", "arguments": {…}}` | 调用**没执行**（它以为写了文件，磁盘上没有），JSON 连同 `\n`、表格 `\|` 一起印进气泡 |
| **截断的**裸 JSON | 同上，但 JSON 永远配不平（回复被截断） | 同上；按"配平 JSON"的判据**永远抓不到** |
| JSON 头 + DSML 参数标签 | `{"name": "library_read"> <parameter name="doc">…`、`{"invoke name="make_figure">`、`{"name": "review_audio", "parameter name="path">…` | 调用**没执行**，标签与正文一起进气泡 |

修（`toolcall.py`）：判据改成两段式 —— `_NAMED_CALL`（`{"name"/"tool":` 与 `{"invoke name=`）+ 
`_ARGS_HINT`（`"arguments":` / `, "parameter` / `<parameter` / `<｜｜DSML｜｜… parameter`，400 字窗口内），
配不平就剪到文本末尾。**代码块内不剪**（成员讲协议格式的示例要留着）。
真实数据复验：近 400 条成员消息，清理后残留从多条降到 **1 条**（在 ``` 代码块里，刻意保留）。

## 三、⚠️ 一个教训：**剪干净显示，反而关掉了一条安全检查**

`router.py` 用「**可见文本里还有没有私有 XML**」判断「这轮回复是坏的 → 换模型重跑」，
而它读的正是 `parse_tool_calls(text)[0]`。把混杂方言从可见文本里剪掉之后，
**这个判据的证据也被剪掉了** —— 一整段私有 XML 看起来像干净回答，被当作"完成的一轮"。
全量回归当场抓到（`test_private_tool_markup_triggers_fallback_instead_of_fake_success`）。

规矩（已写进两处注释）：

1. **`parse_tool_calls` 只剪「它能真正执行的」**（配平 JSON + name + arguments）；**跑不了的形态留在它的
   可见文本里** —— 那是 router 要看的证据。**`strip_hidden` 才是更严的那个**（显示层与存储用它）。
   两个函数回答两个不同问题，合并它们等于关掉一条安全检查。
2. 代码里有一对**互相约束**的测试，改判据前先看有没有成对的那一个：
   `test_private_tool_markup_triggers_fallback_instead_of_fake_success`（顶层私有 XML → 换模型）与
   `test_private_markup_inside_document_arguments_is_preserved`（**合法调用的参数里**引用 XML → 不能误判）。
   第一次改成"读原始文本"，修好第一个、弄红第二个 —— 判据必须在**调用块之外**。

## 四、界面：历史脏消息也清干净了，且没有改库

- `GET /api/groups/{gid}/messages` 对**成员**消息过一次 `strip_hidden`（`main._visible_message`）：
  界面上那些"没有格式"的老消息变干净，**数据库里的原文一字未动**（导出仍可查）。
  注意用户的发言**不清理**（用户消息里可能有素材清单 JSON，那是正常内容）。
- 整条只剩工具调用的消息清完是空串 → 前端**不再画气泡**（`Bubble.tsx` 的 `showBubble` 原来是
  `mine || rest !== "" || decl === null || streaming`，会把空内容渲染成"正在输入"三个点，
  让昨天已结束的消息看起来还在跑）。

## 五、诊断能力：工具崩溃不再吞掉堆栈

`toolhub.py` 的异常处理原来把一切压成一行字，**连文件和行号都没有**。这直接导致下面这条至今没定位：

```
library_read → 工具执行出错:AttributeError: 'NoneType' object has no attribute 'relative_to'
```

**三个群、四个成员、六次调用**都撞在它上面，args 都是工作目录里的长路径（文件多半不存在）。
我逐个读过 20 多处 `.relative_to(`、也照真实 args 写了复现测试，**复现不出来**（说明它依赖真实工作目录
的某个状态）。现在崩溃会记 `logging.exception` 到 `team_agent.tool` 日志，**下次一崩就能定位**。
