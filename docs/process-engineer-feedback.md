# 隐身流程工程师：反馈与联调闭环

## 分工边界

| 角色 | 职责 | 交接内容 |
| --- | --- | --- |
| 群主 | 拆解任务、指定负责人和工具、安排依赖、最终验收 | 任务目标、真实输入路径、工具参数、验收条件 |
| 对话成员 | 规划或制作内容，向工具派工，处理失败并整合输出 | 可执行指令、修正后的输入、交付文件 |
| 工具（如 ComfyUI） | 执行具体生成或渲染任务 | 成功/失败状态、错误原因、实际文件 |
| 隐身流程工程师 | 观察执行证据、提出流程修正、反馈到后续任务、核对重跑结果 | 每群独立的流程日志和下一轮提示 |

工程师不占群聊发言轮次，不作为普通成员出现，也不会自行启动额外的视频生成或渲染任务。后台模型复盘受“让模型补根因与修法”开关控制。

## 一次完整闭环

1. **观测**：收集任务交付、单次工具失败、重复失败、分工错误和成员阻塞。取消任务时保留已经测到的问题，用户主动停止的待执行任务不作为新故障。
2. **记录**：写入该群工作目录的 `流程日志.md`（英文为 `process-log.md`）。任务身份包含负责人、任务内容和交付约定，避免把每轮重复的 `t1` 混为同一任务。同一问题再次出现累加次数；已复核的问题复发会重新打开原记录。
3. **诊断**：群外可用模型根据问题证据、成员角色和近期执行记录提出根因与具体修法。只补目标条目的空白字段，保护人工记录。模型不可用、失败或回答不完整时记录状态，下一轮再试；规则建议仍可使用。
4. **反馈**：开启自动记录时，下一轮最多带入六条未解决问题，按严重程度、反馈次数和复发情况选择。群主与执行成员收到同一组建议；仅适用于当前用户任务和已有工具权限。日志记录“已带入几轮”，不把建议送达冒充修复完成。
5. **复核**：程序检查相匹配的任务或调用是否真正成功。文件任务必须有本次报告且通过路径、存在性、大小、类型及数量检查的产出；仅在工作目录找到同名旧文件不算交付。无关任务成功不会关闭问题。

后台复盘返回后，在群锁内重新读取最新日志再合并；文件使用原子替换写入，避免旧快照覆盖新记录。

## 状态与边界

- `open`：已发现，尚未解决。
- `fixed`：记录了修改，仍待对应重跑验证。
- `verified`：有明确复核证据。自动检测且带操作身份的条目由程序核验，模型不能通过一句 `update` 自行宣称成功。
- `wontfix`：明确决定不处理，保留记录。

自动匹配采取保守规则：任务按负责人、标题、指令、交付要求和结构化参数匹配；工具按成员、工具名和完整参数的摘要匹配。大幅改派或改变输入后，旧问题可能继续待复核，需要结合日志确认；不会猜测其已解决。历史人工条目没有机器身份，须明确提供重跑证据。执行成功与文件交付不代表画面、内容或成片质量已经合格，仍由负责成员验收。

## 查看与验证

入口：**设置 → 通用 → 流程工程师 → 反馈与联调复核**。可以查看修正建议、已反馈轮数、复核证据和复盘不可用的原因。关闭自动记录也会停止历史问题自动进入后续提示。

回归测试位于 `backend/tests/test_process_feedback.py`，覆盖真实 Markdown 文件交付、旧文件误判、无关任务误关闭、问题复发、普通群聊工具失败、取消时保留记录、后台并发合并和复盘失败恢复。

本次验证：完整后端回归 1469 项通过、1 项跳过；随后针对最终改动及新增用例的协作与流程回归 103 项通过。前端构建、中英文文案检查及浏览器中的设置开关、刷新、状态展示通过。
