## 实测发现及修改

| 触发情况 | 根因 | 修改 |
| --- | --- | --- |
| 成员只说“现在写入”，文件不存在 | 只给文本工具说明；路由还丢弃了流式原生工具调用 | 提供正式函数参数结构，重组工具调用分片；明确不支持正式接口的服务回退到文本协议 |
| 文档参数包含真实换行、或只少最外层右括号 | 原解析器把完整正文丢掉 | 保留合法字符串内容，只修复可严格验证的外层括号；不猜测被截断的正文 |
| 输出达到模型上限仍被当成成功 | 未检查流式 finish_reason | 截断回复不能进入执行；记录原因并按路由回退 |
| 一直检索，最后不写文件 | 工具轮数耗尽、交付重试丢失前次材料 | 最后一轮提示落盘；保留前次原始材料；交付重试优先实际调用工具；未执行的调用明确记失败 |
| 检索 `PMID 3082145 Smoker…` 返回零条 | 将 PMID 连同说明当成关键词 | 识别开头的 PMID，转换成精确 UID 查询；保留实时返回的题名、作者、DOI 和摘要 |
| 图片生成成功但无法审查 | JPEG 数据使用了 PNG 扩展名 | 图片发给视觉模型前识别真实 MIME；文件可保留原路径 |
| 朗读了任务说明、没有克隆 | 非推理工具拿到的是任务说明；没有参考音频；Qwen 参数拼写错误 | 区分逐字旁白与任务说明，正确传递参考音频，修正 Qwen 参数；超长旁白拒绝执行而非静默截断 |
| 对话成员被分配另一个工具成员的命令 | 只校验旁听成员，未校验普通成员的工具边界 | 对全部成员检查可执行工具；不兼容计划先修复，不能直接派发 |
| 没有 WAV 也显示完成 | 文件验收正则漏了音频扩展名 | WAV/MP3/M4A 等均按真实非空文件验收；检索成功不能替代声音交付 |
| 对话成员无法把整理后的台词交给克隆引擎 | 只能在计划时给工具成员参数，缺少运行时入口 | 增加 `synthesize_speech`，复用已登记音色和现有合成路径；保留执行开关、权限检查与工具日志 |
| 想用照片工作流却运行了文生视频 | 工具只有全局默认工作流；成员绑定的模型与任务说明不一致 | 普通成员可明确选择已登记、已启用的工作流；绑定模型的生成成员拒绝冒充其他模型；计划必须提供结构化 prompt 与参考参数 |
| 已有音频输入的 ComfyUI 工作流仍被拒绝 | 在进入工作流检查前，所有非方舟参考音频一律被挡住 | 允许 ComfyUI 的单个音频输入，再检查工作流是否真正有 audio 插槽及文件边界 |
| 自报正文约 3000 字，实际不足 | 模型估算字数 | 写文件结果返回可复现的汉字及非空白字符计数，排除 Markdown 标题与参考文献章节 |
| 验图失败仍可进入下一环 | 文件存在即通过，未检查计划要求的视觉/听觉核验 | 必须成功执行所要求的核验；医学内容是否合格仍需独立判断 |
| 群主在规划阶段先做成品，任务板又做一遍 | 规划与执行共用所有工具 | 规划仅允许读取；制作交给任务板；自动模式的单步操作另开一次执行阶段 |
| 同一份原稿转 Word 时被模型重新写短 | 让成员重复输出全文，存在截断和内容漂移 | write_document 支持 source_path，安全读取本群 .md/.txt 全文直接转换 |
| 生成音频检查失败，检查参考录音却使节点通过 | 只看最后一次审听调用 | 按检查输入分别跟踪，只有同一输入的成功重试才能消除其失败 |
| 有明确 prompt 仍检索无关风格资料 | 生成成员无条件进入提示词改写 | 明确提供的结构化 prompt 直接执行，不重复检索或改写 |
| 任务板显示完成但 AI 复核要求返工 | 执行状态与质量标签混用 | 显示“已执行”；复核不通过时显示“待返工”；无评分显示“质量未复核” |
| 指定交付路径与任务专属目录相互冲突 | 两段指令没有优先级 | 指定交付路径优先，任务目录用于中间文件或未指定路径的产物 |
| 已审听 WAV 无法交给成片装配 | 装配器只有重新 TTS 的入口 | 增加 audio_file、audio_start、audio_duration，真实音频区间测量、路径校验、不静默丢弃旁白；原稿仅作字幕 |
| 补写状态时又合成一次旁白 | 交付重试只保留模型原文，未保留工具文件和审查记录 | 将上次工具证据传给重试，保留原文件和失败核验，续写状态不能清除审查失败 |
| 段7状态文件失败导致独立段8也被跳过 | 把安排先后误写成数据依赖 | 规划明确 needs 仅表示输入依赖，独立配音段不能为排序虚连依赖 |
| Word 显示字面 ** 标记；索引重复标题 | 文档导出不处理行内加粗和同名首标题 | DOCX 输出真实加粗 run，保留未闭合/代码字样；同名 title 和正文首标题只输出一次 |
| 群成员只能读 Word 正文，无法检查页面 | 缺少文档页面渲染工具 | 新增 render_document，将本群 DOCX/PDF 输出为带来源哈希和页码范围的 PNG，再由群内 review_picture 逐页验收 |
| 多群同时撞到 Moonshot 并发/RPM 限制 | 限速处理仅作用于单次模型请求 | 同服务商账户共享串行队列，按实际 max RPM 错误学习请求间隔，跨模型共用 |
| 接口余额不足却提示稍等重试 | 429 额度耗尽与短暂限速混为一谈 | 明确识别余额/计费额度错误，不作短暂重试；暂时隔离同账户其他模型，按既有链回退，手动连接检查可确认充值恢复 |
| 旁听钩子偶尔先收到结束再收到开始 | 每个观察事件各自启动子进程，实际启动次序不保证 | 同一钩子、同一群的通知按提交顺序排队，不阻塞其他群；结束后释放队列引用 |
| 没有审图服务就整份计划被拒绝，本地 Word 页面也无法生成 | 计划校验将暂不可用的验收工具等同于错误分工 | 仅当全群均无此验收能力时保留明确跳过节点，独立生产照常执行，依赖验收的下游继续阻断；选错负责人及未知工具仍拒绝 |
| 图片接口 HTTP 500 被解释成临时故障 | 只按 HTTP 状态码解释，忽略响应中的账户额度错误 | 聊天与图片共用额度错误识别；账户额度耗尽优先于 429/500 的泛化提示，保留原始失败原因 |
| 工具已经成功，后续模型失败却把文件交接记录一起清空 | 异常路径只发 message_discard，没有保存本轮工具结果 | 中断消息保留工具参数、结果、文件及中断原因；任务保持失败，阻断依赖下游，禁止因该失败自动重做制作 |
| 新群由分镜成员担任主持人 | 推荐排序没有单独保留协调角色 | 自动补选协调成员，返回 host_ref，界面按推荐主持人初始化 |

长文与分镜多次超过原先 60 秒的整次响应时限，实测配置已调整为 180 秒；没有把生成视频的超时当作聊天超时使用。

## 尚需解决的机制边界

- 当前强制门槛检查真实文件、文件类型、数量、工具错误以及要求执行的审看/审听。**内容医学正确性仍非确定性门槛**；视觉模型也会误判血管连接。任务板的质量标签是 AI 复核信息，不是医学认证。
- 评分模型根据回复摘录可能漏看已有文件，或与后续整合补写结果不同步；评分不能单独推翻磁盘事实。以真实文件和对应版本核验为准。
- 生成图像对复杂血管拓扑及精确引线仍不可靠。多次同类失败应保留缺陷和候选版本，改为可验证的结构约束方案；不能为了变绿而擅自放宽验收标准。
- 规划隔离、同源转换、音频复用、重试证据及服务商限额修复均已在全部群空闲后加载；9个原有群、成员和扩展绑定保留。
