# Team Agent — 多模型 Agent 群聊工作台(v0.5.0)

像微信群聊一样,把国内外不同的大模型拉进同一个群,让它们**按各自强项分工**、互相 @ 协作,用于办公、视频制作、创作等场景。
模型路由与增删基于 [LiteLLM](https://github.com/BerriAI/litellm);优先调用 DeepSeek,失败或「外呼」被禁用时自动回退到本地模型(Ollama + Qwen)。

## 架构

```
Electron 桌面壳 ── React + TS 界面(主界面 ≈ WorkBuddy;设置 ≈ Cherry Studio)
        │ HTTP + WebSocket(仅本机 127.0.0.1:8765)
        ▼
Python 后端 (FastAPI)
  ├─ 编排器  orchestrator.py   谁发言、拼上下文、@ 交接、工具调用循环、执行群主的分工计划
  ├─ 分工    planner.py        群主输出 <plan> → 校验/排依赖 → 依次执行 → 群主整合
  ├─ 路由层  router.py         成员指定模型 / 按强项挑模型 → 外呼开关 → 逐个尝试 → 回退 → 熔断
  │            └─ LiteLLM     DeepSeek / Kimi / 通义 / GLM / 火山 / MiniMax / OpenAI / Claude / Gemini / Ollama …
  ├─ 模型目录 catalog.py + strengths.py + modelopts.py   内置目录 + 实时清单 + 强项标签
  ├─ 工具    toolhub.py toolcall.py   文本协议的工具调用;内置工具 + 插件 + MCP 统一调度
  ├─ MCP     mcp_client.py     官方 mcp 包:stdio / SSE / streamable HTTP
  ├─ 资料库  library.py        txt/md/csv/json/html/pdf/docx → 分片 → BM25(含中文二元组)
  ├─ 记忆    memory.py         全局/群/成员 × 偏好/事实/决定/教训/做法;自动提炼 + 手动管理
  ├─ 提示词  prompting.py      全局系统提示词、提示词库、群提示词、{{变量}}
  ├─ 更新    updater.py        GitHub:程序本体 / 模型目录 / 技能 / 插件 的检查,以及技能/插件/MCP 搜索
  └─ 存储    store.py + store_ext.py   SQLite(~/.team-agent/team-agent.db)
```

## 快速开始

```bash
scripts/dev-setup.sh            # 建 venv、装后端和前端依赖(含 mcp、pypdf、python-docx)
scripts/setup_local_model.sh    # 安装 Ollama 并下载 qwen2.5:7b 作为本地兜底(可选但强烈建议)
cd desktop && npm run dev       # 启动:自动拉起 Python 后端并打开桌面窗口
```

首次打开后:左下角头像 → **设置 → 模型服务 → DeepSeek** 填入 API 密钥(不填也能用,会直接走本地模型),回到首页选一个场景或**群聊模板**,写下任务,回车即自动建群并开始协作。
只想在浏览器里看:`cd backend && python -m app` 后 `cd desktop && npm run dev:web`,打开 http://localhost:5173 。

## 第四阶段新增的能力

### 1. 让每个模型的强项真正用起来(「不能各说各话」)
- **强项标签**(固定 10 个):写作、代码、推理、长文本、多模态、速度、低成本、中文、工具调用、本地。模型的强项由「模型系列 + 名称 + 目录里的能力/上下文」**推断**(可在模型行手动改、也可恢复自动);成员有「岗位强项」。
- **成员没指定模型时,按岗位强项挑最合适的模型**(同分时云端优先、本地留作兜底,再按路由链顺序);挑不到才走路由链。
- **群主分工(任务板)**:群里 ≥2 人且没有 @ 人时,群主先判断要不要分工(设置里可选 自动 / 总是 / 不分工,每个群也可单独设)。要分工则输出计划:总目标、**全组统一约定**(名称、口径、语气、篇幅——防止各说各话的关键)、任务(负责人、依赖、所需强项、建议工具、交付物)。程序校验计划(负责人必须是群成员、依赖不成环、任务数封顶、未知工具丢弃)后按依赖顺序执行,下游成员拿到上游的完整成果,最后群主整合。
- **每个成员开口前先亮明分工**:「【分工】我负责…;发挥…强项;用…(工具/技能);承接…」,界面上显示为高亮的「分工声明」条;任务板卡片实时显示每个任务的负责人、强项、工具、状态。
- 每个成员的系统提示词里都有一张「群成员与分工」表(谁的强项是什么、用什么模型、有哪些技能),并标出「← 这是你」。

### 2. 模型:所有型号都能挑,更新也能看到
- **添加模型** = 「选择模型」对话框:该服务商名下的全部型号(内置目录 + 服务商实时清单 + 已添加),每个型号显示简介、上下文、档位、强项、状态(新 / 预览 / 旧版 / 已停用 / 服务商清单里已没有;本地模型显示是否已安装与体积)。可按强项筛选、只看新模型、刷新实时清单、手输目录外的型号。
- 「新」= 上次看过之后新出现的型号(第一次打开时现有的都算看过)。
- 内置目录是 **2026-09-20** 的整理(部分型号 ID 是根据命名规律推断的);强项标签是**启发式标签,不是评测成绩**。想知道服务商此刻真的提供什么,点「刷新实时清单」。

### 3. 群聊里随时加成员、加扩展
群聊右侧面板三个标签页:**成员**(分工总览;随时把已有成员或预设岗位——主持、评审、记录、资料员、程序员、翻译、分析师、策划、编辑、质检、研究员、风控、项目经理——拉进群;设为群主)/ **扩展**(给本群挂 技能、插件、MCP、资料库范围、记忆开关、分工模式;列出本群实际可用的工具)/ **提示词**(本群提示词、套用提示词库、查看某个成员实际收到的完整系统提示词)。首页有 5 个常用的**群聊模板**(办公文档、视频制作、创作写作、头脑风暴、评审会),更全的在**设置 → 模板中心**。

### 4. 技能 / 插件 / MCP 三者分开,并且真的能被调用
- 成员回复里可以调用工具:**文本协议**(`<tool_call>{JSON}</tool_call>`),不依赖各家 function calling,国内外和本地模型都能用;每条回复最多 3 次调用、最多 N 轮(设置可调)、有超时;调用过程显示为气泡下的工具胶囊(可展开参数与结果)。
- 内置工具:`current_time`、`library_search`、`library_read`、`memory_search`、`memory_save`。
- **技能**:纯文本提示词(`SKILL.md`),分「成员技能」和「群聊规则」两类(后者挂到整个群,全员遵守,如评审会/头脑风暴/接力创作/辩论规则)。
- **插件**:`~/.team-agent/plugins/*.py`,**是在本进程里运行的 Python 代码,没有沙箱**。在群里启用后其工具才对成员可见。
- **MCP**:stdio / SSE / streamable HTTP,首次用到才连接;env / headers 中的密钥接口只返回掩码。MCP 服务器是本机进程,以你的权限运行。

### 5. 资料库
上传 txt / md / csv / json / html / pdf / docx(或新建笔记),切片建索引。成员需要时通过 `library_search` / `library_read` 检索;每个群可选「全部 / 仅选定 / 关闭」;消息里写 `#文档标题` 可直接引用整篇。文件只存在本机数据目录,**但检索到的片段会随问题发给所用的模型(云端模型会收到)**。

### 6. 记忆
- 三层范围(全局 / 群 / 成员)、五种类型(偏好 / 事实 / 决定 / 教训 / 做法)。每次回复前按 BM25 + 置顶 + 新近度召回,注入提示词。
- 群聊结束后由较便宜的模型自动提炼偏好/决定/教训,多步或用过工具的任务会记录「做法」;下次类似任务时,群主做分工会参考以往的做法。可在设置里关闭自动提炼。
- 自动提炼会过滤明显的密码、密钥、长数字串(**尽力而为,不保证**);提炼可能调用云端模型。所有记忆都可在「记忆」页查看、编辑、置顶、删除。

### 7. 提示词
「提示词」页:**全局系统提示词**(可编辑、变量点选、token 估算、按真实成员/群代入预览、恢复默认)+ **提示词库**(仿 Cherry Studio 的添加提示词:标题、内容、`{{变量}}`、预览、token 数、「全局使用」)。可随时套用到某个群的「本群提示词」。

### 8. 更新与发现(GitHub)
**设置 → 更新与发现**:检查 程序本体(Releases 版本比较)、模型目录、已安装技能/插件的上游变化、各服务商的新模型;搜索 GitHub 上的技能 / 插件 / MCP。后台按设置的间隔自动检查(可关闭;外呼关闭时不联网)。

**刻意保留的安全边界**:
| 类型 | 行为 |
| --- | --- |
| 文本技能、模型目录 | 可以更新;技能自动更新**默认关闭**;目录只是 JSON 数据,经过格式校验 |
| 插件(Python 代码) | **永不自动安装**:必须先看完整源码,勾选确认,并带着预览时算出的 sha256 才能安装,服务器会重新下载比对,内容变了就拒绝 |
| MCP 服务器 | **只提供预填表单**,命令由你确认后保存,不自动安装 |
| 程序本体 | **只提示新版本和发布页**,不自动下载、不自动替换 |
GitHub 上的内容一律视为不可信输入。程序仓库默认为空(需自己填 `owner/repo` 才会检查程序本体)。可选填 GitHub Token(不需要任何权限,只为提高接口频率上限;与 API Key 一样存进系统钥匙串,备份导出默认不含)。

### 9. 本地模型:推荐目录、硬件评估、自动发现新版本
**设置 → 本地模型**:
- **推荐目录不只千问**:按厂商列出当前主流开放权重模型(Qwen、Gemma、gpt-oss、DeepSeek、GLM、Nemotron、Granite、Mistral、Phi、LFM、OLMo、编程 Agent 类……),每个型号带体积、上下文长度、许可证、强项标签。目录随程序附带一份快照(`backend/app/data/local_models.json`),「更新与发现」可从 GitHub 拉取更新的版本覆盖它(只是 JSON 数据,经格式校验)。
- **这台电脑跑得动吗**:读取本机内存、磁盘、GPU 加速方式(Apple 芯片 / NVIDIA / 无),每个型号标「宽裕 / 很紧 / 装不下」,没有 GPU 加速的大模型标「会很慢」,磁盘不够也会提示;拉取过大的模型前会二次确认。**这是经验估算,不是保证**(阈值:体积 ≤ 内存 50% 为宽裕,≤ 80% 为很紧)。
- **自建 DeepSeek**:DeepSeek-V3(GitHub 仓库只有代码,不含权重)已被 **V4** 取代;V3 是 671B、V4-Flash 是 284B、V4-Pro 是 1.6T 参数的 MoE,需要多卡服务器,**普通电脑跑不了**。目录里给出 vLLM / SGLang 的启动命令,以及预设「DeepSeek(自建服务)」(OpenAI 兼容,默认 `http://127.0.0.1:30000/v1`)。想在个人电脑上用 DeepSeek,用蒸馏小模型(`deepseek-r1` 系列,基于 Qwen/Llama,不是 V3),或走云端 API。
- **发现新模型 / 新版本**(自动 + 手动「检查」):① 抓 `ollama.com/library` 最新列表;② 对已跟踪系列猜「下一代」名字(如 qwen3.8 → qwen3.9 / qwen4),再用 Ollama 注册表清单验证真的存在并取得体积;③ HuggingFace 和 GitHub 上关注的组织出现的新仓库(仅作提示,标明「不一定能用 Ollama 跑」);④ 检查本机 Ollama 版本是否偏旧。
  **安全边界**:发现只做提示,**从不自动下载权重**;「加入推荐」只是往列表里加一行;GitHub / HuggingFace 内容视为不可信;关闭「允许调用云端模型」时全部不联网。

### 10. 限流、思考型模型、错误信息
- 限流(429,如 Kimi 免费档 RPM=3):非 Ollama 服务商关闭了 SDK 的静默重试;若错误里带「请 N 秒后重试」且 ≤ 5 秒,则**只重试一次**,否则立即回退到链里的下一个模型(最终有本地兜底)。「检测」按钮串行执行,不会并发触发限流。
- 思考型模型只输出了思考过程、没有正文:检测显示「连接正常」,群聊里按失败回退,并提示可能被 `max_tokens` 截断。
- 界面上的错误信息会脱敏(Key 片段、组织 ID、Bearer)并给出中文提示。

## v0.4.0 新增(第五阶段)

### A. 入口重排:技能 / 插件 / MCP / 提示词 / 资料库 / 记忆
侧边栏平铺 6 个入口,「设置 → 工具」分组里也有同样的页面,两处是同一份数据。

### B. 记忆 ⇄ Obsidian 双向同步
**记忆页 → Obsidian 卡片**选一个库里的文件夹(必须是已存在的绝对路径),记忆就以 `.md` 文件同步进去,Obsidian 里的改动也会回到记忆:
- 三方比对(记忆库 / 文件 / 上次同步的快照):只一边改了就带过去;**两边都改了**则以 Obsidian 为准,并把被覆盖的一份放进 `_冲突备份/`。
- 在 Obsidian 里删除的笔记,对应的记忆会删除,但会先把内容放进 `_已删除/`;**一次要删得太多**(超过 5 条且超过一半,或全删)时拒绝,需手动点「强制同步」。
- 新建的 `.md` 笔记会导入为记忆;超过 500 字的长笔记、疑似含密码/密钥的笔记**不会导入**,也不会被截断改写。隐藏目录、符号链接、非 UTF-8 文件名会被跳过。
- 可手动同步,也可开「每 30 秒自动同步」。同一时间只允许一次同步。

### C. 借鉴 Cherry Studio
- **MCP**:内置服务器模板(文件系统、网页抓取、知识图谱记忆、顺序思考、Playwright、时间、Git)只是**预填表单**,不会自动安装;**JSON 导入**(兼容 `mcpServers` 格式,全部校验通过才保存);两个市场入口(mcp.so、Smithery)只是外链。
- **工具权限模式**(设置 → 权限与操控):`只问有风险的`(默认:插件与非只读 MCP 要确认)/ `全部都问` / `全部放行`;可对单个工具「总是允许 / 永远禁止」(禁止优先);审批弹条出现在聊天里,超时或取消一律按拒绝。
- **上下文管理**:历史条数、单条消息截取长度、工具输出长度上限,均可调;**最新一条消息和最近一条用户消息永远不会被截断**。
- **资料库来源**:上传文件 / 新建笔记 / 网页链接 / 本地文件夹(递归、跳过隐藏与符号链接、重复导入只更新有变化的),并有「召回测试」。
- **数据**:备份导出(默认不含密钥;含密钥时 MCP 参数里的疑似密钥也会保留)、从备份恢复(先在临时副本里校验、恢复前自动留一份当前数据的副本)、导出聊天为 Markdown。

### D. 「我添加的模型」直接当群成员
- 群聊右侧**成员卡片**里的下拉可直接选「我添加的模型」;在「设置 → 模型服务」加了模型后,可一键拉进群作为成员;删除模型/服务商时,由它生成的成员一并删除。
- 右侧面板直接展示本群的 技能 / 插件 / MCP,随时添加;左侧栏「成员」下方也可随时把成员加进来。

### E. 模型连通指示灯
每个模型旁有一盏灯:绿=能通、黄=受限(限流/额度/空回复)、红=不通、灰=没测过、灭=已停用。灯来自「检测」结果和真实对话的成败(对话中的成败也会更新);换 Key、恢复备份后旧记录会清掉。指示灯**不是保证**:绿灯只说明最近一次调用成功。

### F. 权限与操控页
设置 → 权限与操控:工具审批模式与超时、总是允许 / 永远禁止清单、外呼总开关、单次请求超时、熔断阈值与冷却时间。后端对越界或类型不对的设置值直接拒绝。

### G. 全链路审查(v0.4.0 收尾)
按「节点 → 逻辑链路」把后端与前端过了一遍,并用静态工具查冗余代码。修掉的问题里比较重要的:
- **编排**:`@Allen` 不再被当成 `@all`、邮箱不再被当成 @;发言准备阶段出错不再让群一直「忙」;分工执行出错会落成「失败」并提示;用户最新消息不再被历史截断。
- **权限**:批准之后再检查一次「永远禁止」;插件工具与内置工具重名时忽略插件;`current_time` 免审批只认内置那个;关闭外呼时远程 MCP 与「测试模型」都不再联网。
- **数据**:恢复备份会先校验再动现有数据,并清掉旧的 Obsidian 关联与指示灯记录;备份与恢复接口要求 `application/octet-stream`(防跨站表单);设置值按类型校验;成员改名不允许空名/重名/含 `@`。
- **前端**:后端断线会显示离线横幅,恢复或 WebSocket 重连后自动补齐消息与审批;发送失败时保留输入框内容;设置保存排队串行,失败有提示;各弹窗遮罩只在「按下与松开都在遮罩上」时关闭;重复点击提交有防抖;未捕获的错误以提示条显示而不是静默。
- 删掉了无用的函数、导入、接口封装与失效的样式。

## 路由规则(router.py)

1. 候选链 = `[成员指定的模型,或按岗位强项挑出的 2 个]` + `设置里的优先级链`(默认 `deepseek-flash → 本地 qwen2.5:7b`),去重。
2. 「允许调用云端模型」关闭(离线模式)→ 所有非本地服务商直接跳过,**不发出任何云端请求**(更新检查、远程 MCP 也同样被拒绝)。
3. 未配置 Key / 已停用 / 熔断中(连续失败 2 次冷却 30 秒)→ 跳过。
4. 逐个尝试;鉴权失败、网络错误、超时、限流、空回复都会触发回退;流式中途失败会清空半截内容后换下一个模型重来。
5. 链里没有本地模型时,自动追加已启用的本地模型兜底(Ollama 优先)。
6. 每条消息都记录实际使用的模型和每次尝试的结果。

## 本机安全

后端只监听 `127.0.0.1`。桌面版每次启动由 Electron 生成随机 token,之后所有 `/api` 与 WebSocket 请求都必须带它;同时校验 Host 头。**API Key 与 GitHub Token 存在系统钥匙串里**(macOS 登录钥匙串,`service=team-agent`),库中只留一个 `keychain:` 引用 —— 备份、导出、随手拷走的 `.db` 文件都不含明文密钥;钥匙串不可用时(非 macOS 或被锁)会回退成明文存储 —— 当前用的是哪种方式,可通过 `/api/system` 的 `key_secret_backend`(`keychain` / `plaintext`)查看。API Key、GitHub Token、MCP 的 env/headers 接口只返回掩码;数据库导出默认清除这些密钥(导出时可选择带上,便于换机器)。外部链接只允许 http(s) 交给系统浏览器。
**插件与 MCP 会在你的机器上以你的权限执行代码,请只启用信任的。**

## v0.5.0 新增(第六阶段)

### 真机联调修复(由你的 Mac 上跑 WorkBuddy 联调发现)
- **SQLite ≥ 3.51 的 `no such column: rowid`**(会让整个聊天记录接口 500,群里所有成员「发言出错」):外层查询不再引用子查询里的 rowid。**如果你看到这个报错,说明跑的还是旧代码,升级后重启即可。**
- 苹果芯片上装了 Intel 版 Python(Rosetta)时,硬件判断改为按真实芯片识别为 Metal;开着 Clash 等代理时,回环地址(本地 Ollama、本机 MCP)自动加进 `NO_PROXY`;熔断冷却结束后失败计数清零;限速(429)按提示的等待秒数重试;版本号按数字比较(`1.10.0` 新于 `1.9.0`);Electron 窗口加了 `will-navigate` 拦截与 preload 收紧;插件工具重名时后来的插件报错而不是悄悄顶掉先来的;分工计划失败时不再出现互相矛盾的两句话。

### 外部智能体:WorkBuddy 作为群成员(设置 → 外部智能体)
- **接法**:WorkBuddy 应用包里自带 CodeBuddy Code 命令行引擎(`.../app.asar.unpacked/cli/bin/codebuddy`),有无界面模式 `-p --output-format stream-json`。本程序每轮把群聊记录交给它、读它的流式输出、把回复作为该成员的发言。**不会去操控 WorkBuddy 的窗口,不读它的账号/会话/密钥,不改它自己的任何设置(包括「允许完全访问」)。**
- **默认关闭**:设置里有总开关,不打开就不能创建、也不会运行;「禁止外呼」开着时不运行(它要连云端模型)。
- **权限三级,默认只读**:只读(读文件/检索,不能改文件、不能跑命令、不能上网)/ 可改文件(不含命令行)/ 完全(要勾选风险确认)。可单独放开「上网」。可改文件与完全级别的工作目录不能是根目录或整个主目录。真机实测:只读级别下 Bash 与 Write 被拒绝、可改文件级别下 Write 成功且 Bash 被拒绝、关闭上网时 WebFetch 被拒绝;被挡下的操作在群里会标「被拒绝」。
- **边界**:外部智能体不能当群主;它的回复只当聊天文字,**不会**被当作分工计划或工具调用来解析执行;只用白名单环境变量启动(不带本程序令牌、不带任何模型服务商的 Key);取消/超时会杀掉整个进程组;运行时会再次校验配置(防被篡改的数据库/恢复的备份)。
- **它的特点**:每次发言是一个独立进程,没有跨轮记忆(上下文靠群聊记录);第一次要等几十秒(实测约 40 秒,后面约 7 秒)。「只读」的工作目录只是起点,**不是围栏**——它读得到你账户能读的其他文件。

### 模板中心:现成的团队、角色、技能、提示词(设置 → 模板中心)
- **打开就能用**:模板随程序分发,不用 clone 任何仓库、不用填路径、不联网、不跑任何脚本。点一下「建成群聊 / 创建成员 / 导入技能 / 存入提示词库 / 添加 MCP」即可,全程只往本机数据库和 `skills` 目录写文本。
- **内容是本程序自己写的**(不含任何第三方项目的文件或数据),所以随程序分发不产生第三方许可义务。当前共 **51 条**:12 个团队模板、13 个岗位角色、12 个技能、7 条提示词、7 个 MCP 用法(目录版本见界面标题旁)。
- **一键建成群聊**会一次把成员、群主、群规则、依赖的技能都装好:成员按名字复用已存在的,不会重复建;群名重复时自动加序号(「办公文档 2」),不会覆盖你已有的群;随附技能若已存在就保留你本地那份,只有点「重新导入」才会覆盖为模板版本。
- **幂等**:重复点同一个模板不会产生重复的技能、提示词或 MCP。MCP 导入后**一律是停用状态、不填任何密钥**,要核对命令后自己到「MCP」页启用。
- **首页只放常用的 5 张团队卡片**,其余 7 个团队模板只在模板中心里,避免首页堆满。
- **放你们自己的模板(可选)**:把 JSON 放进数据目录的 `templates/` 子目录就会自动出现在这一页(改完刷新即可,不用重启)。格式见页面底部的「格式说明与示例」:支持 `team` / `agent` / `skill` / `prompt` 四类;格式不对的条目会被跳过**并在界面上写明原因**,不会静默忽略。为安全起见**不接受 `mcp`**(那等于让一个 JSON 文件决定本机执行什么命令),命令类请到「MCP」页自己添加。

### 首页群聊模板
- 首页的「群聊模板」与模板中心是同一份数据(所以两处不会漂移);点一下就用 `预设岗位` 补建缺失成员并建群。
